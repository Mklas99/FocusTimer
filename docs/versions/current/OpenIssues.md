# FocusTimer - Next-Version Open Issues

> This is the working backlog for the next version. Items are derived from `Planning.md` and have not yet been committed to a release scope.

The remaining OI-24 palette work and OI-29 imported-theme selection have an [implementation plan](../../../openspec/changes/archive/2026-10-08-optimize-theme-readability/proposal.md), with [design decisions](../../../openspec/changes/archive/2026-10-08-optimize-theme-readability/design.md) and [tasks](../../../openspec/changes/archive/2026-10-08-optimize-theme-readability/tasks.md). It includes harmonizing each built-in palette and preserving later personal taste adjustments. The plan does not mark either issue delivered.

| OI-14 | Activity tracking | Foreground-window polling and segmentation cannot be configured. | Partial | `configure-activity-polling` implements Developer Options polling of 1–60 seconds, default 10, with live application and safe capture scheduling. | OI-15 | Worklog management | Logged entries cannot be edited or deleted. | Completed | The Worklog window's Entries tab edits an entry's window title, project, and duration (the application and start stay fixed; a new duration moves the end, never into another day) and deletes entries after a confirmation. Both use the stored revision, so a stale revision, a missing entry, a file in use, or an unsupported schema gives a specific message and a reload. Start and end are not edited directly. The F-03 Windows walkthrough was confirmed complete by the user on 2026-10-08; OpenSpec change archived on 2026-10-08. |
| OI-16 | Distribution | Installer size and release variants. | Implemented; install validation open | Clean build: self-contained MSI 36.04 MiB, .NET-aware setup 13.10 MiB, compressed portable EXE 46.34 MiB. The setup checks for .NET 8 and downloads the verified runtime only when missing; the setup's detection/download path is untested (no environment without .NET 8 preinstalled set up yet). The build also produces a direct framework-dependent MSI (12.16 MiB), still built as the setup's chained payload but no longer published as a release asset — it only served a managed-deployment scenario this personal project doesn't have. Trimming currently fails on ThemeService JSON serialization warnings (IL2026); verify install, upgrade, runtime download, and same-version variant switching before release. |
| OI-17 | Performance | Broader resource costs need measurement and optimization. | Partial | `configure-activity-polling` implements a bounded Windows process-lifetime cache and configurable sampling. [Release evidence](ActivityPollingPerformance.md) confirms component lookup reduction; whole-app savings are unmeasured. Settings reads and worklog writes remain separate investigation areas. |
| OI-18 | Test infrastructure | Persistence tests write to the real AppData settings path and fail in restricted environments. | Completed | Delivered by M02: implemented settings file path injection in JsonSettingsProvider; tests execute in isolated temporary directories. |
| OI-19 | Quality reporting | SonarQube does not receive the locally generated coverage artifacts. | Completed | Delivered by M02: switched CI to windows-latest runner, enabled OpenCover report output across all test projects, and connected coverage ingestion in sonar-scan workflow. |
| OI-20 | Data evolution | There is no agreed general strategy for migrating persistent worklog formats between releases. | Investigate | Research installer versus first-run migration, portable upgrades, backups, idempotent recovery, rollback, and eventual removal of legacy migration code. This is intentionally outside the development-only worklog-foundation change. F-03 adds the `manual` capture source (no schema version change); an older build reads such rows as malformed records (a warning) instead of losing them, and F-03 also changes the tracker to close segments at 23:59:59, so older files may contain entries that end exactly at midnight, which stay readable and editable. |

Theme palettes are separate.  The user confirmed the combined native interaction review complete on 2026-10-08. |
| OI-22 | Worklog management | Users cannot add time they forgot to track. | Completed | The Entries tab adds a manual entry for a chosen day: start time, duration (`2h 30m` or `2.5h`), optional window text, optional project. | OI-23 | Reporting | Users cannot see recorded work as a chronological timeline. | Partially delivered | The Worklog window's Timeline tab draws one day along a time axis in start order, with a vertical zoom (Ctrl + mouse wheel, Ctrl + plus/minus/0, or buttons) that is remembered between runs in `worklog-view.json` beside the settings file, and a Group by switch (all together, by application, by project, by window) that shows one column per group with its total time. | OI-24 | UI / theming | Settings controls look dated and theme colors reduce readability. | Completed | Appearance groups Timer widget colors and Dialogs and notifications colors as peer cards, stacked at narrow widths. Warning and Danger now mark warning/error notification headings and outlines, with a 15-second timeout; information uses 5 seconds. Success remains reserved for future use. Notifications now use the supplied rounded-dialog reference: a wider card, muted readable body text, compact borderless close control, and shared primary acknowledgement action; severity headings and thin outlines remain explicit. Native interaction verification passed; the change is [archived](../../../openspec/changes/archive/2026-10-02-preserve-settings-appearance-during-apply/verification.md). The dense-frost, compact-row/peer-card, Segoe UI, icon-underline, and soft-rounded refresh is implemented for Settings and Worklog ([visual proposal](../../../openspec/changes/archive/2026-10-08-adopt-dense-frost-design-system/proposal.md)); the control chrome items above are delivered by it.
