# FocusTimer - Next-Version Open Issues

> This is the working backlog for the next version. Items are derived from `Planning.md` and have not yet been committed to a release scope.

| ID | Area | Open issue | Status | Notes |
|---|---|---|---|---|
| OI-01 | Global Hotkeys | Hotkeys cannot be edited in Settings. | Open | Registration and dispatch work; only capture, validation, and saving are missing. |
| OI-02 | System Tray | The tray menu has no quick actions such as project switching. | Open | Define the smallest useful action set before implementation. |
| OI-03 | Widget UI | Window position and size are not persisted. | Open | No window-bounds settings exist; restoration must protect against off-screen placement. M01 only supplied canonical base dimensions and spacing. |
| OI-04 | Settings / Reporting | There is no breakdown or user-facing report by app or project. | Partially delivered | F-02 adds a breakdown by application or project, built on a reusable summary service. F-03 moves it into the tray-opened Worklog window, adds a by-window grouping, and lets the user pick a single day (OI-33). Still open: broader time ranges, filter controls, and day grouping. |
| OI-05 | Diagnostics | Settings has no action to open the logs folder. | Open | Logging itself is already available. |
| OI-06 | Cross-platform | Linux implementations remain incomplete. | Open | Linux parity needs a platform target and real implementations for platform services. |
| OI-07 | Data features | Versioned worklog foundation with durable identity and provenance. | Completed | Delivered by F-01: `TimeEntry` has durable entry/session IDs, capture/activity/platform metadata, revision, and safe CSV storage. |
| OI-08 | Data features | Project tagging is manual only. | Open | Rules-based application/window pattern mapping is proposed. F-02 introduced an `IProjectResolver` seam so rule-based detection can replace the stored-tag resolver without changing summaries. |
| OI-09 | Persistence | CSV is the only storage backend. | Open - investigate | Evaluate actual reporting and editing needs before committing to a storage migration. |
| OI-10 | Focus modes | Pomodoro work/break automation is absent. | Open | Separate product decision from existing break reminders. |
| OI-11 | Focus modes | Break and resume events have no optional sound cues. | Open | Needs an accessibility-conscious enable/disable setting. |
| OI-12 | Reporting | Worklog exports and reusable export presets are absent. | Open | Existing export functionality applies only to themes. |
| OI-13 | Widget UI | Minimise behavior is confusing and easy to miss. | Completed | Removed the widget's Minimize button and its click handler. Tray Show/Hide remains available, and Show restores an already minimized window. The widget now has equal top and bottom content spacing. Compact mode intentionally has no Reset button, and Settings is accessible through the tray menu only. |
| OI-14 | Activity tracking | Foreground-window polling and segmentation cannot be configured. | Partial | `configure-activity-polling` implements Developer Options polling of 1–60 seconds, default 10, with live application and safe capture scheduling. Segmentation rules remain open; the main specs are synchronized and the change awaits archive. |
| OI-15 | Worklog management | Logged entries cannot be edited or deleted. | Implemented (F-03); verification/archive open | The Worklog window's Entries tab edits an entry's window title, project, and duration (the application and start stay fixed; a new duration moves the end, never into another day) and deletes entries after a confirmation. Both use the stored revision, so a stale revision, a missing entry, a file in use, or an unsupported schema gives a specific message and a reload. Start and end are not edited directly. |
| OI-16 | Distribution | Installer size and release variants. | Implemented; install validation open | Clean build: self-contained MSI 36.04 MiB, .NET-aware setup 13.10 MiB, compressed portable EXE 46.34 MiB. The setup checks for .NET 8 and downloads the verified runtime only when missing; the setup's detection/download path is untested (no environment without .NET 8 preinstalled set up yet). The build also produces a direct framework-dependent MSI (12.16 MiB), still built as the setup's chained payload but no longer published as a release asset — it only served a managed-deployment scenario this personal project doesn't have. Trimming currently fails on ThemeService JSON serialization warnings (IL2026); verify install, upgrade, runtime download, and same-version variant switching before release. |
| OI-17 | Performance | Broader resource costs need measurement and optimization. | Partial | `configure-activity-polling` implements a bounded Windows process-lifetime cache and configurable sampling. [Release evidence](ActivityPollingPerformance.md) confirms component lookup reduction; whole-app savings are unmeasured. Settings reads and worklog writes remain separate investigation areas. |
| OI-18 | Test infrastructure | Persistence tests write to the real AppData settings path and fail in restricted environments. | Completed | Delivered by M02: implemented settings file path injection in JsonSettingsProvider; tests execute in isolated temporary directories. |
| OI-19 | Quality reporting | SonarQube does not receive the locally generated coverage artifacts. | Completed | Delivered by M02: switched CI to windows-latest runner, enabled OpenCover report output across all test projects, and connected coverage ingestion in sonar-scan workflow. |
| OI-20 | Data evolution | There is no agreed general strategy for migrating persistent worklog formats between releases. | Investigate | Research installer versus first-run migration, portable upgrades, backups, idempotent recovery, rollback, and eventual removal of legacy migration code. This is intentionally outside the development-only worklog-foundation change. F-03 adds the `manual` capture source (no schema version change); an older build reads such rows as malformed records (a warning) instead of losing them, and F-03 also changes the tracker to close segments at 23:59:59, so older files may contain entries that end exactly at midnight, which stay readable and editable. |
| OI-21 | Settings / theming | Settings controls and theme colors are inconsistent, and save/cancel behavior varies by setting. | Partial | Settings has one full draft: Apply and OK validate and commit it, while Cancel and title-bar close restore the last successful commit and temporary appearance preview. All Appearance controls preview immediately, including scale, overall fade, and compact mode; a successful commit preserves exactly that preview. Load, commit, registration drift, and recovery failures have visible feedback and retry paths. The [redesign task](OI-21-SettingsRedesign.md) still covers the optional nonappearance immediate-change setting, remaining control styling, and theme alignment across widget/menu. |
| OI-22 | Worklog management | Users cannot add time they forgot to track. | Implemented (F-03); verification/archive open | The Entries tab adds a manual entry for a chosen day: start time, duration (`2h 30m` or `2.5h`), optional window text, optional project. It is stored with the fixed application "Manual entry" and the new `manual` capture source, and is allowed even when automatic logging is off. The day must be inside the retention window and the entry must end by 23:59 and not in the future. |
| OI-23 | Reporting | Users cannot see recorded work as a chronological timeline. | Implemented (F-03); verification/archive open | The Worklog window's Timeline tab draws one day along a time axis in start order, with a vertical zoom (Ctrl + mouse wheel, Ctrl + plus/minus/0, or buttons) that is remembered between runs in `worklog-view.json` beside the settings file, and a Group by switch (all together, by application, by project, by window) that shows one column per group with its total time. Overlapping entries sit side by side, gaps stay empty, and manual entries are marked by label and outline (not color alone). It shows the same read warnings as the Entries tab. Ranges beyond one day remain open. |
| OI-24 | UI / theming | Settings controls look dated and theme colors reduce readability. | Partial | Appearance has one Color Palette accordion with Timer Widget and Dialogs & Notifications in two columns. Settings text, field, and tab roles are wired to theme resources; their checked text pairs reach 4.5:1 and selected/focus indicators reach 3:1 across all seven built-in themes ([contrast check](../../../design/SETTINGS_THEME_COLOR_CONTRAST_CHECK.md)). Apply now keeps the Settings content visually enabled, locks editing, and shows a reserved saving status. Play/Pause has a dedicated normal color; widget hover/pressed/disabled icon colors are wired in both modes. Success and Danger remain reserved for future use. Native interaction verification passed; the change is [archived](../../../openspec/changes/archive/2026-10-02-preserve-settings-appearance-during-apply/verification.md). Still open: refresh action buttons, checkbox/slider chrome, dropdown and other control visuals (especially Light), and verify expansion and scrolling in a resized Settings window. |
| OI-25 | Widget UI / theming | The background opacity control no longer makes the widget visibly transparent. | Partial | M03 replaces the opaque base/panel pair with one shell tint and keeps foreground opacity separate. Off uses the tint slider; Solid is fully opaque and ignores its preserved value. Blur is hidden because it looked the same as Off or solid on the tested Windows compositor. The see-through frost goal remains open in OI-28; M03 is verified and archived; OI-21 and OI-24 remain open. |
| OI-26 | Developer workflow | VS Code F5/Start can launch a different build than the documented Host `win-x64` run command, showing stale UI. | Open | Identify the selected launch configuration and align the build and executable paths with `dotnet run --project src/FocusTimer.Host --runtime win-x64`. Local `.vscode` changes are ignored by Git, so a reproducible repository setup is still needed. |
| OI-27 | Settings persistence | A valid older settings file without `deviceId` loses its loaded preferences for the current run if the identity migration write fails. | Open | Settings writes now use same-directory atomic replacement, protecting the prior JSON. The migration still throws on a denied write; return the parsed settings with a process-stable ID and log the failure, then add a denied-write regression case. |
| OI-28 | Widget UI / theming | Platform blur cannot guarantee a visibly see-through frosted background on every Windows compositor. | Planned | Prototype a Windows native composition backdrop brush behind sharp widget controls, with background tint opacity separate from blur. Desktop capture is excluded. A temporary DWM Desktop Acrylic test made the widget look solid despite a successful API result; do not re-enable Blur until a visibly distinct effect is verified. Measure performance over light/dark content, compact/full modes, and remote or reduced-transparency fallbacks. Keep Linux blur behavior as a separate platform investigation under OI-06. |
| OI-29 | Settings / theming | Imported themes have no selectable custom/imported entry in the theme preset dropdown. | Open | Add a custom/imported entry and restore its selection consistently when reopening Settings and after restarting the app. Import currently selects "Custom", but the dropdown lists only built-in themes. Preserve the saved theme colors and appearance values; displaying the selection must not reload a built-in preset. Verify import, Apply/OK, reopening, restart, and Cancel after further edits. |
| OI-30 | Developer diagnostics | Live application logs cannot be read inside Settings. | Open | Show current application diagnostic logs in Settings when Developer mode is enabled, with new messages appearing while the window is open. Keep this separate from worklog records and the OI-05 logs-folder action. Define bounded history, scrolling, and refresh behavior so continuous logging does not block the UI. |
| OI-31 | Worklog inspection | Users cannot inspect raw worklog entries in a table. | Implemented (F-03); verification/archive open | The Entries tab shows one day's stored entries (start, end, and duration to the minute, application, window, project) with the exact times, source, entry ID, session, revision, last modified, end reason, project source, platform, and device for the selected row, and a search field (all words, any column; Ctrl + F) that highlights the matches. It uses the same query path as the summary and shows read warnings. |
| OI-32 | Developer activity tracking | Applications cannot be excluded from worklog recording. | Open | In Developer mode, let the user configure applications whose activity must not be recorded. Apply exclusions during capture rather than merely hiding rows in reports; preserve existing worklogs. Define application matching, persistence through Apply/OK/Cancel, and treatment of excluded intervals so their time is not attributed to the next recorded application. |
| OI-33 | Summary reporting | The Summary table cannot display previous days. | Implemented (F-03); verification/archive open | One day selector (previous, next, Today, date picker; no future days; limited to the retention window) drives the Entries, Timeline, and Summary tabs of the Worklog window, and the Summary keeps its grouping when the day changes. This delivers the previous-day portion of OI-04. |
| OI-34 | Error handling / user feedback | Error handling and user-facing errors and warnings have no consistent policy. | Open - investigate | Explore how failures are propagated, logged, and displayed across startup, Settings, tracking, persistence, and reporting. Build on existing Settings retry/recovery and Summary read warnings. Decide severity, when to use inline messages or notifications, useful recovery actions, and duplicate-message handling. Keep detailed diagnostics available in Developer mode while giving users clear explanations, especially when recording or saving fails. |
