# Settings control state audit

## Scope and evidence

This report records the Settings window before the OI-21 redesign. It covers General, Logging, Appearance, Hotkeys, About, and the unlocked Developer Options section. The timer widget layout is outside scope.

Findings marked **code-backed** follow from the repository and Avalonia 11.2.0 control templates. Findings marked **rendering unverified** need a running Settings window. No Settings screenshots were found in the inspected files, and no FocusTimer process was running during the audit. No UI states were observed directly. The [Avalonia 11.2.0 Button template](https://github.com/AvaloniaUI/Avalonia/blob/11.2.0/src/Avalonia.Themes.Fluent/Controls/Button.xaml) and [Expander template](https://raw.githubusercontent.com/AvaloniaUI/Avalonia/11.2.0/src/Avalonia.Themes.Fluent/Controls/Expander.xaml) were consulted for template state behavior; other Fluent controls are identified as template-owned without asserting their exact rendered colors.

## Diagnosis

Settings loads Fluent, then the project token, resource, and control style files ([`App.axaml:6`](../src/FocusTimer.App/App.axaml#L6)). Shared Settings styles cover headings, labels, scrolling, accordion containers and headers, swatches, and tooltips. Tabs, ordinary buttons, checkboxes, fields, combo boxes, and sliders otherwise depend mainly on Fluent. The `minimal-slider` class used on Appearance has no matching rule in `ControlStyles.axaml` ([`SettingsWindow.axaml:208`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L208), [`ControlStyles.axaml:1`](../src/FocusTimer.App/Styles/ControlStyles.axaml#L1)). This is a **code-backed** split in state ownership, not proof that the rendered controls look inconsistent.

The most consequential gaps are the identical visual role of OK, Apply, and Cancel; no shared Settings rule for selected versus focused tabs or expanded versus focused accordion headers; swatches whose bound color may be hidden by Fluent hover and pressed template states; and field alignment that changes between pages ([`SettingsWindow.axaml:410`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L410), [`ControlStyles.axaml:88`](../src/FocusTimer.App/Styles/ControlStyles.axaml#L88), [`ControlStyles.axaml:119`](../src/FocusTimer.App/Styles/ControlStyles.axaml#L119)). The visual effect of each needs rendering verification.

Behavior also changes what the visual states mean. Theme edits apply to the running app immediately, Cancel only closes, and save failures are logged without feedback in the window ([`SettingsWindowViewModel.cs:410`](../src/FocusTimer.App/ViewModels/SettingsWindowViewModel.cs#L410), [`SettingsWindowViewModel.cs:425`](../src/FocusTimer.App/ViewModels/SettingsWindowViewModel.cs#L425), [`SettingsWindowViewModel.cs:640`](../src/FocusTimer.App/ViewModels/SettingsWindowViewModel.cs#L640)). OI-21 already specifies draft, preview, restore, and failed-save behavior; styling should follow those decisions ([`OI-21:11`](../docs/versions/current/OI-21-SettingsRedesign.md#L11)).

## Page findings by impact

### General

- **Medium, code-backed:** Checkboxes appear in a single vertical stack, but the reminder interval is a two-column row whose input begins after an auto-sized label. Its alignment therefore differs from the 120 px retention input on Logging and the fixed-column rows on Appearance ([`SettingsWindow.axaml:27`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L27), [`SettingsWindow.axaml:46`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L46)).
- **Medium, code-backed:** Disabling reminders disables acknowledgement and interval, while leaving their stored values intact. Verify that the disabled text and controls remain legible in every theme. Whether the dependency is sufficiently obvious is **rendering unverified** ([`SettingsWindow.axaml:40`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L40)).

### Logging

- **Medium, code-backed:** The worklog path is a read-only TextBox beside a Browse button separated by a local 5 px margin. Its row has an extra 10 px bottom margin in addition to the page's 15 px stack spacing and the section-header margins ([`SettingsWindow.axaml:64`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L64), [`SettingsWindow.axaml:71`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L71), [`ControlStyles.axaml:62`](../src/FocusTimer.App/Styles/ControlStyles.axaml#L62)).
- **Medium, behavior decision:** Turning off work logging leaves directory browsing and retention enabled, unlike the disabled reminder dependents on General. Decide whether these are allowed draft preferences while logging is off; style them to match that decision ([`SettingsWindow.axaml:67`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L67), [`SettingsWindow.axaml:85`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L85)).

### Appearance

- **High, code-backed:** Both palette accordions start expanded and contain 16 hex fields and swatches before opacity controls, diagnostics, and widget options. At the 640 × 540 default size, lower sections require scrolling as a layout inference; the exact extent is **rendering unverified** ([`SettingsWindow.axaml:9`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L9), [`SettingsWindow.axaml:125`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L125), [`SettingsWindow.axaml:203`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L203), [`SettingsWindow.axaml:269`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L269)). Preserve a clear route to presets, color editing, opacity, and diagnostics without designing a compact Settings window.
- **High, code-backed:** Palette labels use 126 px columns; opacity and scale labels use 140 px columns. Preset buttons each use 80 px widths and 10 px left margins. Hex rows use 6 px top margins; the first row does not. The first palette grid has an unused row, and the opacity and scale grids begin at row 1 after removed controls ([`SettingsWindow.axaml:105`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L105), [`SettingsWindow.axaml:127`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L127), [`SettingsWindow.axaml:204`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L204), [`SettingsWindow.axaml:292`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L292)).
- **High, code-backed risk:** Each swatch uses its sampled color as the Button background. Fluent hover and pressed template states may obscure the sample. The 28 px target meets the project's 24 px minimum, but every swatch tooltip says only “Open color picker”; its field name is supplied visually by a separate TextBlock, with no explicit accessibility association ([`SettingsWindow.axaml:128`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L128), [`ControlStyles.axaml:119`](../src/FocusTimer.App/Styles/ControlStyles.axaml#L119), [`Tokens.axaml:40`](../src/FocusTimer.App/Styles/Tokens.axaml#L40)).
- **Medium, code-backed:** The diagnostics card has its own border, background, radius, 8 px padding, 8 px top margin, and four text rows. It competes with the editing sections for hierarchy; its actual visual prominence is **rendering unverified** ([`SettingsWindow.axaml:269`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L269)).
- **Medium, behavior decision:** Built-in selection, import, reset, and color edits preview immediately. Import chooses `Custom`, which is absent from the picker source. Invalid hex input has no explicit field error, and parsing failures are logged by `ThemeManager` ([`SettingsWindowViewModel.cs:225`](../src/FocusTimer.App/ViewModels/SettingsWindowViewModel.cs#L225), [`SettingsWindowViewModel.cs:510`](../src/FocusTimer.App/ViewModels/SettingsWindowViewModel.cs#L510), [`SettingsWindowViewModel.cs:586`](../src/FocusTimer.App/ViewModels/SettingsWindowViewModel.cs#L586), [`ThemeManager.cs:191`](../src/FocusTimer.App/Services/ThemeManager.cs#L191)).

### Hotkeys

### About and unlocked Developer Options

- **High, code-backed:** Version unlock is attached to `TextBlock.PointerPressed`. A hand cursor and tooltip hint at clicking, but the TextBlock has no focusable action or key handler; the seven-click unlock is not available through that element with Tab, Enter, or Space ([`SettingsWindow.axaml:313`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L313), [`SettingsWindow.axaml.cs:43`](../src/FocusTimer.App/Views/SettingsWindow.axaml.cs#L43)).
- **High, code-backed:** The activity polling interval has a separate validation message using `SettingsLabelTextBrush`, without an explicit error border, error role, or association with the NumericUpDown. Invalid values block Apply, but there is no page-level feedback for a user on another tab ([`SettingsWindow.axaml:354`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L354), [`SettingsWindowViewModel.cs:170`](../src/FocusTimer.App/ViewModels/SettingsWindowViewModel.cs#L170), [`SettingsWindowViewModel.cs:425`](../src/FocusTimer.App/ViewModels/SettingsWindowViewModel.cs#L425)).
- **Medium, code-backed:** About uses 12 px stack spacing versus 15 px on the other tabs. The log-level picker uses a 120 px label column and 180 px field; its interval label and 120 px NumericUpDown stack vertically. Repository Open is 70 px wide. ### Navigation and footer shared by all pages

- **High, code-backed:** OK, Apply, and Cancel sit in one right-aligned row with identical 80 px widths, 10 px spacing, and no footer boundary or primary action treatment. The row remains outside page scrolling ([`SettingsWindow.axaml:409`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L409)). Whether Fluent differentiates a keyboard default action is **rendering unverified**; no project `accent` class or `IsDefault` property is assigned.
- **Medium, code-backed:** XAML tab order is General, Logging, Appearance, About, Hotkeys, while OI-21 and the Settings spec name Hotkeys before About ([`SettingsWindow.axaml:23`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L23), [`SettingsWindow.axaml:306`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L306), [`SettingsWindow.axaml:373`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L373), [`settings/spec.md:8`](../openspec/specs/settings/spec.md#L8)).
- **Medium, code-backed:** Labels are plain TextBlocks. No `TabIndex`, access keys, or explicit label-to-control or automation-name associations appear in the Settings XAML. Ordinary Button content and CheckBox content identify their actions; iconless swatches and the version unlock rely on adjacent text or tooltips. Actual focus order and screen-reader names need manual verification ([`SettingsWindow.axaml:23`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L23), [`SettingsWindow.axaml:128`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L128), [`SettingsWindow.axaml:313`](../src/FocusTimer.App/Views/SettingsWindow.axaml#L313)).

## Behavior and visual feedback decisions for OI-21

- Theme changes are applied by `OnThemePropertyChanged` and theme-object replacement before Apply or OK. Cancel and title-bar close do not restore the preview. This affects any visual draft or dirty state ([`SettingsWindowViewModel.cs:640`](../src/FocusTimer.App/ViewModels/SettingsWindowViewModel.cs#L640), [`SettingsWindowViewModel.cs:658`](../src/FocusTimer.App/ViewModels/SettingsWindowViewModel.cs#L658), [`SettingsWindowViewModel.cs:410`](../src/FocusTimer.App/ViewModels/SettingsWindowViewModel.cs#L410), [`SettingsWindow.axaml.cs:51`](../src/FocusTimer.App/Views/SettingsWindow.axaml.cs#L51)).
- Apply saves the settings and raises `SettingsApplied`; OK runs Apply and closes only after `LastApplySucceeded`. A failed save is logged but not shown. The footer has no progress or failure state ([`SettingsWindowViewModel.cs:425`](../src/FocusTimer.App/ViewModels/SettingsWindowViewModel.cs#L425), [`SettingsWindow.axaml.cs:51`](../src/FocusTimer.App/Views/SettingsWindow.axaml.cs#L51)).
- Import and export errors are logged without feedback. Reset changes the theme service and draft theme immediately. These actions need visible result and failure states under OI-21's draft model ([`SettingsWindowViewModel.cs:510`](../src/FocusTimer.App/ViewModels/SettingsWindowViewModel.cs#L510), [`SettingsWindowViewModel.cs:549`](../src/FocusTimer.App/ViewModels/SettingsWindowViewModel.cs#L549), [`SettingsWindowViewModel.cs:586`](../src/FocusTimer.App/ViewModels/SettingsWindowViewModel.cs#L586)).
- The developer interval is validated as a whole number from 1 to 60 before saving. General and Logging NumericUpDown controls use local bounds. Theme hex fields have no comparable validation path. Treat error feedback as a behavior and accessibility requirement, not just an error color ([`SettingsWindowViewModel.cs:170`](../src/FocusTimer.App/ViewModels/SettingsWindowViewModel.cs#L170), [`SettingsWindowViewModel.cs:425`](../src/FocusTimer.App/ViewModels/SettingsWindowViewModel.cs#L425)).

## Focused design checklist

- Define Settings-specific roles for page surfaces, primary and muted text, input text, borders, selection, keyboard focus, invalid fields, and actions. Do not derive Settings action colors from widget button colors ([`OI-21:26`](../docs/versions/current/OI-21-SettingsRedesign.md#L26)).
- Set one spacing and geometry rule for rows, labels, fields, checkbox targets, slider value columns, accordion headers, and buttons. Remove empty grid rows and unexplained local offsets.
- Give tabs independent selected and focused cues. Give accordions independent collapsed, expanded, hover, pressed, disabled, and focused cues. Ensure template-part styles control the pixels that render.
- Keep the sampled color visible inside each swatch in every interaction state. Give each swatch a field-specific accessible name and a clear focus target.
- Separate the footer from scrolled content and identify Save/OK as the primary commit action. Keep Apply, Cancel, Browse, Open, Import, Export, and Reset distinguishable by role and context.
- Make read-only values recognizable, provide keyboard access to the developer unlock, associate labels and errors with their controls, and show invalid and save-failure feedback beyond color.
- Implement OI-21 draft, preview, restore-point, import, reset, Cancel, and title-bar-close decisions before finalizing dirty, busy, error, and disabled button states.

These checks follow the project's [state and focus standard](UI_DESIGN_STANDARD.md#L334), [spacing standard](UI_DESIGN_STANDARD.md#L289), and [Settings guidance](FOCUSTIMER_UI_ADDENDUM.md#L146).

## Manual verification checklist

- On every tab, use Tab and Shift+Tab to record focus order and indicator visibility. Use Enter and Space on buttons, checkboxes, and accordion headers; use arrow keys on tabs, combo boxes, sliders, and numeric fields. Check whether read-only fields add unnecessary stops. Verify a keyboard path to Developer Options.
- For each control type, inspect applicable normal, hover, pressed, selected or checked, disabled, invalid, and keyboard-focus states. Test selected and focused tabs separately, expanded and focused accordion headers separately, and each swatch while hovered, pressed, and focused.
- Check disabled reminder dependents; an invalid developer interval; invalid hex text; failed import and export; and a failed settings save. Confirm that feedback names the affected field or action and remains understandable without color.
- Check Appearance with both palette accordions expanded and collapsed. Confirm that presets, color editing, opacity values, diagnostics, and footer actions remain reachable at the normal 640 × 540 size and current 500 × 400 minimum. Record any clipping; do not design a compact layout as part of this audit.
- Repeat Settings state checks with Dark, Light, Monokai, Solarized Dark, Nord, Dracula, High Contrast, and an imported theme ([`ThemeService.cs:115`](../src/FocusTimer.Core/Services/ThemeService.cs#L115)). Check text, border, selection, focus, swatch, and action contrast. Record the imported theme's picker label.
- Once OI-21 behavior is implemented, edit across tabs and exercise Apply, Save/OK, Cancel, title-bar close, and failed save with immediate changes on and off. Confirm that the visible controls match the draft, active preview, and last successful restore point.
